# Research Note: Issue R04 - Execution Failure Conversion to Success

- **Date**: 2026-10-08
- **Issue**: R04 (Run execution error turning into success in `console/runs.py::_watch_run_process` when execution.json is corrupted or exit=0 with failures)
- **Component**: `codontrace.console.runs`
- **Standard Reference**:
  - POSIX IEEE Std 1003.1-2017 process exit semantics.
  - RFC 8259 (The JavaScript Object Notation (JSON) Data Interchange Format) section 8.1 on parse failure fail-closed behavior.
- **Model Assumptions**:
  - Exit code 0 indicates normal termination of the runner process, but NOT necessarily scientific success of all batch seeds/workers.
  - Scientific execution status is authoritative in `output/execution.json`.
  - If `execution.json` cannot be parsed (truncated, corrupted, invalid JSON), the run MUST fail-closed (`status = "FAILED"`).
  - If `execution.json` contains `complete != True` or contains entries in `validation_failures`, `errors`, or `failed`, the run status MUST be `"FAILED"`.
- **Prior Art / Nearest Flaw**:
  - `_watch_run_process` had an `except Exception:` block around `json.loads(exec_json.read_text())` which caught parse errors and defaulted to `new_status = "COMPLETED"`.
- **Proposed Difference**:
  - If `json.loads` raises an exception: set `new_status = "FAILED"`, `error_reason = f"Corrupted execution report (JSONDecodeError): {exc}"`.
  - Validate that parsed JSON root is a dictionary; otherwise fail with "Corrupted execution report (root not dict)".
  - Check `rep.get("complete") is True`, `not rep.get("validation_failures")`, `not rep.get("errors")`, and `not rep.get("failed")`. If any condition fails, mark as `"FAILED"` and capture the precise failure reason.
- **Testable Prediction**:
  - Corrupted `execution.json` with exit code 0 produces `status == "FAILED"` with explicit `errorReason`.
  - `execution.json` with `complete: false` or validation errors produces `status == "FAILED"`.
- **Decision**:
  - Implement fail-closed verification in `_watch_run_process`, `get_run_details`, and `list_simulation_runs`.
