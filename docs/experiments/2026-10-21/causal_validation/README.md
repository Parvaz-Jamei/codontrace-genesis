# Identified effects vs. engine reruns, and replay decomposition

Regenerate with `python docs/experiments/2026-10-21/causal_validation/run_validation.py`
(about 40 s). `result.json` records the commit it ran from (the parent of the
commit that adds it), the package version and the Python version. All draws
use fixed seeds: two runs from clean checkouts with different
`PYTHONHASHSEED` values gave byte-identical files (sha256 `180b1c83…`).
`tests/causal_inference/test_causal_validation_result.py` (marked `slow`)
reruns the script and compares its output with this file byte for byte,
with `commit` and `python` copied over.

## Design

Engine: `GenesisRuntimeProfile.life_loop_world`, 12 ticks, unmodified.
Variables: `env:population` (founding population 4 or 8), `bit:1` (focal
founder-genome bit), `bit:2` (background bit), `event:births` (number of
birth events). `do(bit:i = b)` edits the founders that carry the preset's
primary genome and runs the engine on that edited genome.

Observational sample: each unit draws a seed (0-7), an environment and a
background from `RNGManager`; the focal bit is then assigned with
P(bit:1 = 1 | env, bg) = 0.2, 0.3, 0.6, 0.85, so the focal bit is confounded
with both. The assumed diagram is `env -> bit:1`, `bit:2 -> bit:1`,
`env -> births`, `bit:2 -> births`, `bit:1 -> births`.

ID returns the back-door formula
`sum_{bit:2, env} P(bit:2) P(env) P(births | bit:1, bit:2, env)`; it is
estimated by plug-in on the sample, with a 400-draw bootstrap interval. The
ground truth comes from fresh engine runs on `truth_seeds` 1000-1007, a pool
disjoint from the observational seeds: every (truth seed, environment,
background) cell is run under `do(bit:1 = 0)` and `do(bit:1 = 1)`,
environment and background are averaged with the design's weights, and
`truth_ci_ate` is a t-interval over the eight truth seeds. The truth is the
same for all three assignment seeds.

## Result (`result.json`, three assignment seeds, 400 units each)

| assignment seed | identified ATE [95% bootstrap] | truth ATE [95% t, truth seeds] | naive contrast |
|---|---|---|---|
| 0 | 5.23 [4.76, 5.75] | 4.84 [4.65, 5.04] | 8.75 |
| 1 | 4.80 [4.25, 5.34] | 4.84 [4.65, 5.04] | 9.07 |
| 2 | 4.73 [4.13, 5.27] | 4.84 [4.65, 5.04] | 9.44 |

The identified interval covers the fresh-seed truth every time; the naive
contrast is outside every interval. With the environment unrecorded the
diagram has `bit:1 <-> births` and ID reports the effect as not identifiable
(a hedge); no number is produced.

## Contingency vs. selection

Histories are the two backgrounds (`bit:2 = 0/1`), the treatment is
`do(bit:1)`, and the replicates are eight engine seeds. In both environments
the focal bit has no effect on the `bit:2 = 0` background and a large one on
`bit:2 = 1` (potentiation). The interaction is significant (permutation
p = 0.0005, 1999 permutations; step-down adjusted over the three tests,
p = 0.0015), so the verdict is `historically_contingent`; chance explains
under 0.3% of the variance. Each term is tested by permuting residuals of
the model without that term and adding them back to that model's fitted
values. The decomposition blocks of `result.json` were recomputed from the
recorded tables with that method: the raw p-values, sums of squares and
verdicts are unchanged, and `p_holm` was added. The whole file has since
been regenerated by `run_validation.py`; the decomposition blocks did not
change.

Scope: one preset, a 12-tick horizon, two bits. This is a validation of the
identification machinery against the engine's own interventions, not a claim
about biological evolution.
