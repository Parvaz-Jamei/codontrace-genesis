# برنامه تحقیق ده ایده با sensor swarm

هر ایده حداکثر پنج فاز دارد. هر فاز: پنج دور طوفان فکری، تقسیم کار توسط مدیر، ساخت، دو دور بررسی نقص، آزمون، دو دور بررسی نتیجه؛ در صورت نقص دو بار چرخه اصلاح تکرار شود. این چرخه برای پیدا کردن اشکال است، نه دستکاری نتیجه تا مثبت شود. قبل هر فاز، HEAD و وابستگی‌ها ثبت و سرچ منابع اولیه جدید با تاریخ/DOI یا URL انجام شود. اگر روش موجود کافی نیست، تیم راه‌حل بین‌رشته‌ای را پیشنهاد و با baseline مقایسه کند؛ «نوآوری» نام‌گذاری جای شواهد نیست.

چهار کدر: قرارداد/transport؛ coordinator/موتور؛ policy/آزمایش؛ پنل/LLM. دو tester مستقل: correctness/security؛ design/statistics/reproducibility. مدیر مسئول pin کردن commit، issue log، کنترل تغییر scope و dataset manifest است.

قواعد مشترک: هر سنجه کنترل مثبت مصنوعی و کنترل منفی/no-effect را بگذراند؛ ظرفیت نمونه‌برداری برای lag/نوسان بررسی شود. seed واحد مستقل داده واقعی نیست: board/day/run مستقل یا cluster تعریف کنید. داده زمانی را random row split نکنید؛ hold-out زمان/برد/محیط. training، انتخاب capsule، pilot و confirmatory test جدا. primary metric و حداقل اثر مفید پیش از test نهایی قفل شوند؛ CI خوشه‌ای متناسب طراحی، اصلاح چندآزمونی و effect size گزارش شود. test ناموفق نیز آرشیو شود. باگ را اصلاح کنید اما runs تحت specification متفاوت را مخلوط نکنید. پذیرش یافته مثبتِ معتبر و یافته منفی هر دو لازم‌اند. firmware و استفاده از actuator خارج این پچ هستند.

## H01 اعتماد وابسته به زمینه

**پرسش:** آیا اعتماد کالیبره در زمینه جدید از mean/median بهتر است؟

**مسیر V1:** calibrate + fusion. **سنجه‌ها:** MSE، coverage و خطای هنگام fault مشترک.

1. **طراحی و سرچ:** مرور کارهای مستقیم و نزدیک؛ تعریف واحد آزمایشی، اختلاف با prior art، فرضیه ابطال‌پذیر و معیار عملی؛ کنترل‌ها: mean، median، وزن ثابت؛ آموزش بدون دسترسی به مرجع test.
2. **اعتبار ابزار:** اجرای probe مصنوعی موجود، سپس کنترل مثبت/منفی اختصاصی روی چند شدت اثر؛ قرارداد پیام، clock و unit بررسی شود. پاس مهندسی ادعای کشف نیست.
3. **pilot سخت‌افزاری:** حداقل چند node Wi-Fi با قابلیت واقعی اعلام‌شده؛ مرجع مستقل، قطع شبکه و خطاهای محدوده‌دار؛ ثبت raw، version، boot، فرمان/ACK، انرژی فقط اگر اندازه‌گیری شده؛ برآورد variance و توان قبل تعیین تعداد runs نهایی.
4. **آزمایش قفل‌شده:** hold-out برد/روز/زمینه؛ budget و هزینه ارزیابی برابر؛ بدون تغییر پارامتر پس از دیدن test؛ اجرای ablation و baseline؛ گزارش CI و اندازه اثر با استقلال صحیح.
5. **تکرار و انتشار شواهد:** تکرار مستقل، raw path برای هر عدد، commit/dependency/seed/clock provenance، موارد شکست، بازپخش journal و تصمیم درباره supported/not-supported/inconclusive بر اساس طرح قفل‌شده.

3. **pilot سخت‌افزاری:** حداقل چند node Wi-Fi با قابلیت واقعی اعلام‌شده؛ مرجع مستقل، قطع شبکه و خطاهای محدوده‌دار؛ ثبت raw، version، boot، فرمان/ACK، انرژی فقط اگر اندازه‌گیری شده؛ برآورد variance و توان قبل تعیین تعداد runs نهایی.
4. **آزمایش قفل‌شده:** hold-out برد/روز/زمینه؛ budget و هزینه ارزیابی برابر؛ بدون تغییر پارامتر پس از دیدن test؛ اجرای ablation و baseline؛ گزارش CI و اندازه اثر با استقلال صحیح.
5. **تکرار و انتشار شواهد:** تکرار مستقل، raw path برای هر عدد، commit/dependency/seed/clock provenance، موارد شکست، بازپخش journal و تصمیم درباره supported/not-supported/inconclusive بر اساس طرح قفل‌شده.

## وضعیت اجرای V1

ده probe از رفتار واقعی توابع این پچ عدد تولید می‌کنند، ولی همه synthetic هستند. آزمون‌های مهندسی شامل خطا و no-effect هستند. مجموعه به‌تنهایی هیچ discovery، بهبود روی برد، consensus غیرمتمرکز یا biological Red Queen را ثابت نمی‌کند. همکاری nodeها فعلاً با هماهنگ‌کننده Genesis انجام می‌شود؛ خودسازمان‌دهی توزیع‌شده و یادگیری داخل firmware توسعه مستقل‌اند.
