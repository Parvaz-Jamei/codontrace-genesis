Core PR-2 — Incremental execution primitive، نه UI hook

در core فعلی run_ticks() بعد از اجرای tickها _build_result() را صدا می‌زند. اگر Studio برای live demo هر بار run_ticks(1) بزند، هر tick evidence/replay/source digest کامل rebuild می‌شود. راه درست، یک primitive عمومی و UI-agnostic است؛ نه callback، نه WebSocket، نه async server.

# API پیشنهادی؛ نام نهایی با maintainer تعیین شود.
# این API برای execution/replay است، نه UI.
class GenesisEngine:
    def step_tick(self) -> GenesisTickResult:
        """Advance exactly one deterministic generation/tick without final artifact build."""

    def latest_engine_frame(self) -> EngineFrame:
        """Return EngineFrame for the last completed tick only."""

    def iter_engine_frames(self, ticks: int) -> Iterator[EngineFrame]:
        """Yield frames by repeatedly stepping the engine; no transport, no WebSocket."""
        for _ in range(ticks):
            self.step_tick()
            yield self.latest_engine_frame()

    def finalize_run(self) -> GenesisRunResult:
        """Build evidence/replay/manifest once, preserving run_ticks() semantics."""

    def run_ticks(self, ticks: int | None = None) -> GenesisRunResult:

Backpressure: WebSocket معمولی backpressure خودکار ندارد. پس اگر simulation سریع‌تر از UI بود، فریم‌های تصویری coalesce/drop می‌شوند، metrics downsample می‌شود، ولی replay/evidence کامل روی دیسک ذخیره می‌ماند.

Benchmark baseline الزامی

# tools/profile_phase1.py در core یا scripts/benchmark_phase1.py
import cProfile, pstats
from codontrace.genesis import GenesisEngine, GenesisExperimentSpec

def batch_run():
    GenesisEngine.from_spec(GenesisExperimentSpec(tick_count=50, seed=7)).run_ticks()

def naive_live_loop():
    engine = GenesisEngine.from_spec(GenesisExperimentSpec(tick_count=50, seed=7))
    for _ in range(50):
        engine.run_ticks(1)  # fallback کند: هر بار final result ساخته می‌شود

with cProfile.Profile() as pr:
    batch_run()
stats = pstats.Stats(pr).sort_stats("cumtime")
stats.print_stats(30)
