# Research Note: Issue R19 - LLM Fallback Contract and Scientific Analyst Grounding

- **Date**: 2026-10-08
- **Issue**: R19 (LLM fallback contract in `chat.py`)
- **Component**: `codontrace.console.chat`
- **Standard Reference**:
  - George R. Price (1972): "Extension of covariance selection mathematics", *Annals of Human Genetics*, 35(4): 485–490.
  - Price equation multigroup partition:
    $$\Delta \bar{z} = \frac{1}{\bar{W}} \operatorname{Cov}(W_g, \bar{z}_g) + \frac{1}{\bar{W}} \sum_g q_g \operatorname{Cov}(w_{gi}, z_{gi})$$
  - Fault tolerance design patterns: Graceful degradation with transparent fallback signaling (`fallback: true`).
- **Model Assumptions**:
  - When the external/local LLM endpoint is unavailable or fails, the chat API must fulfill its primary contract: graceful fallback to the deterministic, domain-knowledge evolutionary analyst.
  - The fallback answer must never be replaced by a raw connection failure message unless explicitly asked for raw errors.
  - The response schema must faithfully report `source: "analyst"`, `mounted: false`, and `fallback: true` when a requested LLM fails over.
  - Scientific domain responses must accurately cite the Price equation multigroup partition with proper normalization $(1/\bar{W})$ and group frequencies $q_g$.
  - Rather than dogmatic hardcoded assertions, the analyst must report evidence dynamically from the run execution telemetry.
- **Prior Art / Nearest Flaw**:
  - `chat_turn` contained an early return that intercepted non-analyst models and returned a bare error message ("Connection to the local LLM failed..."), completely bypassing `_generate_analyst_reply`.
- **Proposed Difference**:
  - Always execute `_generate_analyst_reply` whenever `llm_answer is None`.
  - Accurately set `fallback: True` when falling back from an LLM query.
  - Include the mathematically precise Price equation multigroup partition.
  - Link verdict to run execution telemetry while preserving epistemic invariants.
- **Testable Prediction**:
  - A query with `model=None` or `model="llama-server"` when LLM is offline returns `source: "analyst"`, `fallback: True`, and a complete scientific answer.
- **Decision**:
  - Fix fallback routing in `chat.py` and ensure scientific precision in analyst replies.
