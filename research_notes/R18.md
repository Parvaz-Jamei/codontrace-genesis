# Research Note: Issue R18 - Remote Update Independent Authorization

- **Date**: 2026-10-08
- **Issue**: R18 (Remote update on `/api/release/update` without independent authorization in `console/server.py`)
- **Component**: `codontrace.console.server`
- **Standard Reference**:
  - RFC 6750: The OAuth 2.0 Authorization Framework: Bearer Token Usage.
  - OWASP Top 10 A01:2021 - Broken Access Control.
  - Python `hmac.compare_digest` for constant-time cryptographic token verification.
- **Model Assumptions**:
  - Administrative and repository-modifying actions (such as `git pull --ff-only` on `/api/release/update`) must require explicit, independent authorization.
  - Unauthenticated remote calls (from outside localhost / 127.0.0.1) must be strictly forbidden (HTTP 403 Forbidden).
  - When an admin token is configured (`CODONTRACE_UPDATE_TOKEN`), all callers (including local and remote) must supply the matching token via `Authorization: Bearer <token>`, `X-Update-Token`, or JSON body `token`.
  - Token comparison must use constant-time comparison to prevent timing attacks.
- **Prior Art / Nearest Flaw**:
  - `/api/release/update` directly invoked `update_checkout()` without inspecting client address or requiring any authorization token. Although `_from_this_machine` was defined in `server.py`, it was never called.
- **Proposed Difference**:
  - Implement `_check_update_authorization(body_json)` in `ConsoleHandler`.
  - Validate remote vs local callers via `_from_this_machine(self.client_address[0])`.
  - Require and verify `CODONTRACE_UPDATE_TOKEN` via `hmac.compare_digest`.
  - Reject unauthorized remote requests with 403 Forbidden; reject invalid tokens with 401 Unauthorized.
- **Testable Prediction**:
  - A POST to `/api/release/update` from a simulated remote IP or with invalid token returns 401/403 with an error message and does not invoke git pull.
  - A POST with a valid configured token succeeds.
- **Decision**:
  - Enforce independent token guard and origin boundaries on `/api/release/update`.
