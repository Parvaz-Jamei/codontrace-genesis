# Simulation Atlas — پنل علمی لایه‌ای

این صفحه React به منوی «اطلس لایه‌ها / Layer Atlas» اضافه شده؛ مسیر مستقیم هم `/simulation.html?run=RUN_ID` است. همان کنترل‌های اصلی پنل باقی می‌مانند. Play این صفحه **بازپخش تصویر** است، نه start/resume موتور؛ از کارت اجرای آزمایش برای کنترل worker استفاده کنید.

## قابلیت‌ها

- انتخاب اجرای واقعی و seed؛ کش و پاسخ API بین seedها مخلوط نمی‌شوند.
- نماهای single slice و stack، عمق تاریخچه ۱ تا ۸ نسل ثبت‌شده، فاصله لایه‌ها، zoom و تایم‌لاین.
- play/pause، جلو/عقب، سرعت ۰٫۵ تا ۸ فریم‌برثانیه، loop و follow newest با refresh هر پنج ثانیه.
- عامل زنده، حلقه و علامت مثبت برای تولد ثبت‌شده، ضربدر مرگ ثبت‌شده، خط والد–فرزند و پیوند تولد دووالدی؛ رویدادها صرفاً از metadata واقعی موتور هستند.
- inspector با ID، مختصات، ATP و genome digest. رنگ بر اساس digest است، نه ادعای میزبان/انگل. رنگ‌ها می‌توانند تکرار شوند؛ ID/digest مرجع تشخیص‌اند.
- آمار population/births/deaths/two-parent births؛ مقدار ثبت‌نشده «—» است. تولد دووالدی معادل همه تلاش‌های جفت‌گیری نیست.
- خروجی SVG فریم جاری و ZIP حداکثر ۱۶ تصویر ثبت‌شده نزدیک انتخاب، همراه manifest نسل‌های صادرشده و سقف glyph. هیچ نسل بینابینی ساخته نمی‌شود.
- سقف glyph قابل انتخاب ۲۰۰ تا ۲۰۰۰ برای هر لایه؛ آمار جمعیت کامل است. عامل‌های یک سلول جابه‌جا نمی‌شوند؛ هم‌پوشانی واقعی حفظ می‌شود و می‌تواند بعضی نمادها را بپوشاند.
- متن راهنما، شکل‌های متفاوت، focus و کنترل کیبورد. این‌ها ادعای گواهی کامل WCAG نیستند.

## ثبت هنگام اجرای آزمایش

قبل از run_ticks، در **همان worker هر seed** اضافه کنید:

```python
from pathlib import Path
from codontrace.visualization import SimulationRecorder

# run_directory باید همان ریشه کارت، یا ریشه output آن باشد.
recorder = SimulationRecorder(Path(run_directory), every=1).attach(engine)
result = engine.run_ticks()
recorder.finalize()  # فاصله پایانی ناقص در every>1 هم ثبت می‌شود.
```

Observer موجود موتور استفاده می‌شود؛ core engine، RNG و fitness تغییر نمی‌کنند. `_tick_results[-1]` فقط برای خواندن outcome آخر استفاده می‌شود و قرارداد آن در تست اتصال بررسی شده است. every>1 میزان ذخیره‌سازی را کم می‌کند؛ birth/death بین فریم‌های ضبط‌شده جمع می‌شوند. در every>1 در پایان `recorder.finalize()` را صدا بزنید تا فاصله پایانی ناقص هم با شمارنده‌های واقعی ثبت شود؛ نسل بینابینی نمی‌سازد و روی فریم موجود دوباره نمی‌نویسد.

مسیر داده:

```text
RUN_DIRECTORY/simulation/seed_7/frame_000000000000.json
RUN_DIRECTORY/simulation/seed_7/frame_000000000001.json
```

فریم قبل از اعلام آماده‌بودن، به‌صورت atomic منتشر می‌شود؛ writer رقیب حق overwrite ندارد. برای armهای متفاوتِ یک seed، کارت/دایرکتوری مستقل بسازید. فایل‌های قبل موجود بازنویسی نمی‌شوند. چارچوب console هر script اختصاصی را نمی‌تواند از بیرون مجبور به ثبت موقعیت کند؛ تیم باید recorder را در محل ساخت engine همان script attach کند. گزارش صرفاً آماری برای ساخت صحنه فضایی کافی نیست.

مثال واقعی دیجیتال با سه seed:

```bash
python examples/simulation_observatory.py --output simulation_runs/run_atlas --generations 24 --population 16
python -m codontrace.console --host 127.0.0.1 --port 8765
```

در پنل اجرای `run_atlas` را باز کنید. این مثال خروجی **موتور دیجیتال واقعی** است، نه آزمایش فیزیکی و نه dataset نمایشی دست‌ساز. ممکن است جمعیت منقرض شود؛ صفر واقعی نمایش داده می‌شود. تمهید ضبط، نتیجه را مثبت نمی‌کند.

## تبدیل اجرای ذخیره‌شده

```bash
python -m codontrace.visualization --input core_result.json --output simulation_runs/run_imported
```

ورودی باید نتیجه کامل Genesis با run و ticks/generation_result/population/world_after باشد. گزارش summary-only قبول نمی‌شود. ورودی حداکثر ۶۴ MiB؛ برای اجراهای بزرگ از recorder زنده استفاده کنید. این CLI تبدیل داده است، نه اجرای مجدد. اجرای ناموفق تبدیل را با خروجی تازه تکرار کنید؛ فایل‌های قبلی overwrite نمی‌شوند.

## API و ایمنی

GET `/api/runs/RUN_ID/simulation?seed=7&cursor=0&limit=8`، با توکن API اپراتور مطابق سرویس قبلی. cursor شاخص فریم ضبط‌شده است، نه شماره نسل. هر درخواست حداکثر ۳۲ فریم، هر فایل ۸ MiB و جمع فایل‌ها ۱۶ MiB؛ هر فریم حداکثر ۲۰٬۰۰۰ عامل ثبت‌شده. اگر جمعیت بیشتر است، این نسخه recorder مناسب آن اجرا نیست و باید chunking اضافه شود. اگر صفحه به سقف حجم برسد، کلاینت فریم انتخاب‌شده را مستقل دریافت می‌کند. شاخص هر seed حداکثر ۱۰۰٬۰۰۰ فریم و هر session حداکثر ۲۵۶ seed. streamها نباید engine run_id متفاوت داشته باشند.

پذیرش فایل غیرمتناهی، شمارنده متناقض، symlink خارج کارت، seed اشتباه یا مختصات نامعتبر ممنوع است. در آرشیو، pause و stop موتور مانع خواندن فریم نمی‌شود. توکن در حافظه session می‌ماند. دسترسی به این API readonly است؛ روی برد firmware یا کد دلخواه اجرا نمی‌کند.

## حدود معنا

موقعیت‌ها در مرز نسل ثبت می‌شوند؛ مسیر حرکت درون نسل بازسازی نمی‌شود. عمق عمودی لایه‌ها کدگذاری زمان است، نه مختصات فیزیکی z. ضربدر مرگ روی آخرین موقعیت ثبت‌شده است؛ اگر عامل بین دو فریم متولد و مرده و موقعیتش ضبط نشده باشد، شمارنده مرگ وجود دارد ولی نشان مکان جعلی نمی‌سازیم. پیوندها parentage / تولد دووالدی‌اند؛ این پچ تمام یال‌های causal graph یا تبادل capsule را بدون record مستقل رسم نمی‌کند.

برای تست گرافیکی در مرورگر واقعی: عرض‌های ۳۹۰، ۷۶۸ و ۱۴۴۰؛ حالت paused/stop؛ نسل بدون عامل؛ دو seed با ID عامل یکسان؛ خطای API و تغییر سریع seed؛ تصویر SVG و ZIP؛ سقف ۲۰۰۰ glyph در هر لایه؛ ورود کیبورد و انتخاب عامل. Chromium در محیط ساخت اجرا نشد؛ DOM و API واقعی و رندر مستقل SVG بررسی شده‌اند، ولی تأیید pixel/layout مرورگر ادعا نشده است.

## اصلاحات V3 و ابزار LLM

خروجی sequence قبل از هر import غیرهمزمان، snapshot جدا از فریم‌ها و scope می‌گیرد. اگر کاربر وسط export seed را عوض کند، فایل همان seed اولیه می‌ماند؛ manifest علاوه بر نسل، tick، engine_run_id و شمارنده جمعیت را ثبت می‌کند. کلیک تکراری export تا پایان مسدود است. توکن اختصاصی Atlas بر توکن عمومی console اولویت دارد و فهرست runها پس از تغییر آن دوباره خوانده می‌شود.

ابزار readonly `simulation_inspect` به فهرست ابزارهای LLM افزوده شده؛ پارامترهای ساده `run_id`, `seed`, `cursor`, `limit` دارد. فقط scope اجرای انتخاب‌شده را می‌خواند؛ خروجی جدول شمارنده‌های واقعی و نمودار جمعیت–نسل همراه provenance است. `cursor` شاخص فریم است، `limit` حداکثر ۳۲. در pause/stop نیز آرشیو قابل خواندن است. این ابزار هیچ فرمان برد یا worker صادر نمی‌کند. unknownها به صفر تبدیل نمی‌شوند.

برای انقراض، generation همچنان ساعت بازپخش است؛ tick فعالیت عامل‌ها می‌تواند ثابت شود. نبود آرایه population به معنی «جمعیت صفر» نیست و ورودی رد می‌شود. snapshot اولیه پیوند تولدهای تاریخی را به عنوان رویداد جدید رسم نمی‌کند. lineage نامعتبر و شناسه تکراری، نشان مرگ روی عامل زنده، شمارنده کمتر از نشان‌ها و seed directory غیر canonical پذیرفته نمی‌شوند.

ضبط‌کننده باید در thread اجرای engine attach و finalize شود؛ قفل recorder به معنی thread-safe شدن خود engine نیست. خواندن همزمان فایل‌های منتشرشده از API مجاز است. برای restart/arm متفاوت، directory تازه استفاده کنید؛ تاریخچه قبلی بازنویسی نمی‌شود.
