# Phase 2 Runtime Wiring Matrix

GENESIS Phase 2 extends the Phase 1 strong core into a stronger evolutionary-intelligence and discovery-capability layer. The goal is ambitious: variable genome, executable macro vocabulary, contribution attribution, event evidence, intervention hooks, discovery witness, social/generalization protocols, OEE-candidate evidence, and evidence-gated claim labels.

| Surface | Runtime status | Evidence status | Claim discipline |
|---|---|---|---|
| Variable genome / structural mutation | Runtime-wired through reproduction/mutation paths when configured | `StructuralMutationRecord` v2 with token digests and lineage status | Claims require genome digest, structural mutation record, replay, and artifact digest |
| ADF executable macro | Runtime-wired via bounded registry expansion | Expansion source-map plus `ADFUsefulnessControlReport` | Macro usefulness requires utility/cost/control evidence, not compression alone |
| Contribution ledger | Built from real `CodonExecutionRecord` payloads | Ledger digest plus micro-ablation record | Attribution is not causal proof unless ablation/intervention supports it |
| Innovation protection | Evidence-triggered API remains bounded | Registry digest/status in manifest | Protection must not freeze evolution or make elites immortal |
| EventGraph | Canonical event-evidence graph surface | `event_graph_digest` in manifest | Observed temporal edges are not causal proof |
| Causal intervention | Protocol/artifact surfaces in manifest | `intervention_protocol_digest`, `intervention_result_digest`, `causal_intervention_result_digest` | Strong causal labels require executed intervention/ablation evidence |
| Discovery witness | D0/shadow/persistence/ablation witness surfaces | `discovery_witness_digest` | Discovery labels require witness gates, not metadata-only artifacts |
| Social generalization | Partner/heldout protocol surface | `social_generalization_digest` | Mean fitness alone cannot unlock social intelligence/generalization |
| OEE candidate | Statistical/OEE report surfaces | `oee_report_digest`, `statistical_report_digest` | OEE candidate requires novelty, learnability, persistence, ablation, replay |

No Phase 2 surface should create a second engine or runner app inside core. All surfaces are library primitives, records, manifests, policies, or small smoke examples.
